## 1. Согласование технической основы

### Уже согласованные требования

- Первый релиз: Fedora актуального и предыдущего выпуска, KDE Plasma. Wayland/X11 и формат распространения ещё уточняются.
- Настройки и журнал последних файловых операций хранятся в пользовательских папках приложения. История отмены сохраняется после перезапуска; возможность конкретной отмены зависит от сохранности данных и отсутствия конфликтов.
- Расположение выбирается платформенным слоем, формат настроек и журнала общий для ОС:
  - Linux: настройки — `~/.config/papka/`, история — `~/.local/state/papka/`; учитывать переопределения XDG.
  - Windows: настройки — `%APPDATA%\papka\`, история — `%LOCALAPPDATA%\papka\`.
  - macOS: `~/Library/Application Support/papka/`, настройки и история в отдельных подпапках.
- Журнал обновляется по ходу операции для учёта частичного выполнения после сбоя. Конкретный формат хранения, глубина и срок хранения истории ещё не выбраны; SQLite не согласована.
- История только в текущем сеансе не соответствует требованиям.
- Примеры желаемого интерфейса пользователь предоставит позже. UI — Iced, без HTML и WebView; текущий экран — временная заглушка, не согласованный дизайн.

## 3. Каркас приложения

Платформенные пути реализованы в `platform::AppDirectories::resolve()` с помощью `dirs`: Linux учитывает XDG, Windows использует пользовательские системные папки, macOS — подпапки Application Support. API только возвращает пути, не создаёт каталоги и пока не вызывается интерфейсом. Linux-сборка успешна; отдельный `papka-tester` добавил и выполнил 7 тестов путей — все прошли. Сборки Windows/macOS и запись истории ещё не проверены. Задачи и их статус ведутся только в этом плане; агент реализации выполняет один шаг за один заход.
